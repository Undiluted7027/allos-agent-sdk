### Technical Decisions

1. **No Default Model:** Unlike OpenAI/Anthropic, there's no sensible default for Ollama since users have different models pulled. The `--model` flag is required.

2. **Model Verification:** The provider verifies the model exists on the Ollama server at initialization time, providing immediate feedback rather than failing at chat time.

3. **Tool Calling Whitelist:** Rather than attempting tool calls on all models (which would fail), we maintain an explicit whitelist of models known to support tools.

4. **Metadata Building:** Created synthetic usage objects to maintain compatibility with the `MetadataBuilder` pattern used by other providers.

### Notes

- The native provider is significantly more capable than the `ollama_compat` compatibility mode
- Users should prefer `ollama` over `ollama_compat` for agentic workflows
- Tool calling requires models that explicitly support it (llama3.1, qwen2, qwen3:8b)
