### Technical Decisions

1. **Dynamic Detection with Fallback:** The provider first tries to get actual capabilities from `ollama.show()`. If that fails (older Ollama versions, network issues), it falls back to the static mappings. This ensures compatibility while providing accurate info when available.

2. **Capability Caching:** Capabilities are fetched once during `_verify_model_available()` and stored on the instance (`_model_context_window`, `_model_supports_tools_capability`). This avoids repeated API calls during chat operations.

3. **Model Family Extraction:** The `_extract_model_family()` method intelligently handles version tags (`:latest`, `:8b`, `:instruct`) to match against the known model mappings.
